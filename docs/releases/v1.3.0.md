# v1.3.0 — TokenMeter: OpenAI pricing fallback, cross-project browser, and faster provisional projects

TokenMeter 1.3.0 ships the accumulated `v1.2.0..v1.3.0` delta already on `main`: OpenAI costs now resolve through the host V2 pricing catalog with a bounded `models.dev` fallback and durable 24h/15m caching so zero-price rows estimate correctly, and the TUI gains a native cross-project Usage browser (`TokenMeter: Browse Usage`) that lists every known project with lifetime totals and drills into project and session detail — all filtered, headed, and probed more cheaply than before.

## What changed

### OpenAI pricing through V2 + models.dev fallback and cache

Reported `cost !== 0` remains authoritative. When a row is `providerID=openai` with `cost===0` and billable tokens, the plugin first checks host `api.client.v2.model.list()` `ModelV2Info.cost` via exact `pricingKey` (trim+lower, strip `openai/`, `gpt-5.6`→`gpt-5.6-sol`) and `selectFiniteNonTier` (first non-tier finite quartet, absent `cache_write`→0, no hard-coded tiers). When the host has no usable positive exact pricing — e.g. all 13 `openai` models zero in production — the bounded `https://models.dev/api.json` fallback supplies exact `openai` IDs hydrated once per 24h TTL (15m cooldown on failure, one in-flight coalesced, 8s timeout, no disk persistence), with host-first per-model win `hostPricingMap.get(key) ?? remotePricingMap.get(key)`, tier threshold from payload (`size:272000` for `gpt-5.6-sol`), cache-write non-overlapping, and safe-zero otherwise. Live Project, deleted `tokenmeter.sqlite` tombstones, and every `store` identity `Σ` via `resolveCost`/`resolveEntry` share that chain, so restarts re-estimate deterministically and the cost-identity fix in ([#48](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/48)) prevents overwriting. Covers ([#47](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/47)), ([#50](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/50)), ([#66](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/66)), ([#52](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/52)).

### Cross-project Usage browser with exact headings

`TokenMeter: Browse Usage` (`tokenmeter.browser`, palette `TokenMeter`, `namespace: "palette"` via `api.keymap.registerLayer`, no `api.command`) opens one native host `DialogSelect` at a time via `api.ui.dialog.replace` (once-guarded close, no recursive replace, no stack leak). Navigation is `Projects` (all known projects with lifetime totals from live `session.list({scope:"project", limit:10000})` + deleted aggregate, ★ pinned current, recent sort) → `Project detail` (aggregate, period, last activity, root sessions pinned current, recent sort) → `Session detail` (title/id, lifetime tokens/cost via `resolveCost` — reported non-zero wins, OpenAI zero estimates if pricing exists else safe-zero — last activity, provider groups `providerID` then `modelID` sorted by spend, `fmtCost`/`fmtCompact`, short label last segment, ★ if current, loading/empty/error, `← Back`). Headings are exactly `Current Project` / `Projects` / `Sessions` / `Current Session`; the title is count-only with no Overview tokens/cost. Shipped across ([#67](https://github.com/jonasotoaguilar/opencode-tokenmeter/issues/67)) via the browser foundation and dialog set, landed in ([#109](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/109)) and corrected in ([#110](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/110)).

### Navigation hardening

Usage dialog navigation now survives Back/Close races: `__back`/`__close` handling is idempotent, late async callbacks are generation-guarded so a delayed probe cannot replace a navigated Project/Session detail or reopen a closed browser, and Back returns to that `projectID` without leaking stack entries (fallback browser when the ID is gone). Verified by identical Close harnesses green on `main` and candidate, with production `dist/tui.js` rebuild as remediation when the artifact is stale. Restored in ([#108](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/108)) and kept in ([#109](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/109)) / ([#110](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/110)).

### First-paint provisional projects before V2 probes

First paint no longer blocks on per-project probes. The dialog renders provisional rows immediately from `project.list` + `current` pin (≤100ms, observed ~40ms) filtered by sync eligibility, then finalizes asynchronously with `probeHasSessionsV2` via `api.client.v2.session.list({project, limit:1})`, bounded `BROWSER_CONCURRENCY` (4) plus `withConcurrency`, per-request `FETCH_TIMEOUT_MS` (4s) via `withTimeout`, and a generation guard that prevents late-probe replacement. Optimized in ([#109](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/109)) and retained in ([#110](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/110)).

### Safe project eligibility and V2 presence probes

Provisional and final rows show only safe, eligible projects via `src/tokenmeter/browser/eligibility.ts` (`isEligibleProjectPath`): `existsSync` + `statSync` directory check, `.git` presence, rejected `/`, HOME, or direct child of HOME (`~/foo`), and `isSafeDirectory` (no `parse(root)` roots, no unsafe traversals) — nested `~/projects/foo` remains eligible, invalid/deleted/non-git and root-level entries never flash. Presence probing switched from legacy `project.directories` + `session.list({directory})` to V2 `session.list({project, limit:1})`, cutting backend calls from 58→30 at `N=28` (baseline `1 list + 1 current + 28 directories + 28 session.list(directory)` vs candidate `1 list + 1 current + 28 v2.session.list(project)`), measured in `perf-browser-first-paint` (provisional ≤100ms, final ≤900ms, ≤3 replaces, no unhandled rejections). Implemented in ([#110](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/110)) superseding the legacy directory-probe path.

## Upgrade

From 1.2.0 (or earlier):

- **Pinned users**: set the pin to `1.3.0` in your TUI config, then restart OpenCode.
- **Unpinned users**: OpenCode resolves `latest` on launch — restart OpenCode to pick up 1.3.0.

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["opencode-tokenmeter-tui"]
}
```

OpenCode installs TUI plugins cache-first. To update a cached install, remove the package cache directory and restart:

```bash
rm -rf ~/.cache/opencode/packages/opencode-tokenmeter-tui@latest
```

If you pinned a specific version, remove that version's cache directory instead. No `npm install` step is required. After restart the V2 pricing fallback, Browse Usage browser, corrected headings, and eligibility filtering are live.

## Rollback

`1.2.0` remains a fully loadable published version. If 1.3.0 regresses:

- **Users**: pin back to `1.2.0` in the TUI config (or remove the plugin entry) and restart; report the failure so a `1.3.1` can be cut.
- **Maintainer**: the release pipeline is tag-driven (`v1.3.0` → preflight → publish → verify). A regression is corrected by cutting the next patch tag, not by re-pointing `1.3.0` — npm versions are immutable. Keep this document as the single release record until the next tag renames it.
