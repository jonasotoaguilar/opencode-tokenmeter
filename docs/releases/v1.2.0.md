# v1.2.0 — TokenMeter: compact prompt icons, percentage cache, and project milestone toasts

TokenMeter 1.2.0 ships compact footer instrumentation, a percentage cache mode, lightweight project milestone celebrations, and two Subagents layout fixes. All changes are presentation or notification only; aggregation scopes and accounting remain exactly as in 1.1.1.

## What changed

- **Compact footer icons.** The `session_prompt_right` footer row is now icon-first in stable order `Σ total · ↑ input · ↓ output · 󰧑 reasoning · 󰆼 cache` (`Σ` U+2211 for total, `↑` U+2191 for input, `↓` U+2193 for output, `󰧑` for reasoning, `󰆼` for cache — single codepoints measured via `textColumns`). Segments are joined with ` · ` in the host prompt's muted tone and truncated with `…` at the terminal width; the line never wraps. Each metric and the footer master switch remain toggleable in `TokenMeter: Settings`, and an empty subset renders nothing. Contributed by #43, shipped in #44.

- **Percentage cache mode.** `cache` now has three states: `combined`, `separated`, and `percentage`. `percentage` is the default (previously `combined`); valid persisted `combined`/`separated` values migrate unchanged and invalid values fall back to `percentage`. The cycle `combined → separated → percentage → combined` is driven by the settings palette command. In `percentage` mode the cache segment shows `cache / total * 100` as an integer percent, where `cache = cache.read + cache.write` and `total = input + output + reasoning + cache.read + cache.write`, rounded to the nearest integer, clamped 0–100, `0%` when total is 0. The same semantics apply to the footer `󰆼` and the sidebar secondary rows (`format-cache` seam); `combined` still renders the summed cache and `separated` renders `R<read>|W<write>` with zero sides omitted. Non-percentage magnitudes still respect `compact` vs `precise` number mode. Contributed by #43, shipped in #44.

- **Project milestone toasts.** When the authoritative Project total (live `session.list` at 10_000-session cap plus the persisted deleted-session aggregate) crosses a new decimal order of magnitude starting at `1M` — `1M`, `10M`, `100M`, `1B`, `10B` and onward by powers of ten — TokenMeter emits a single toast for the highest newly reached milestone, for example `TokenMeter · Project reached 10M tokens`, with progressively stronger presentation for higher orders. Milestones fire exactly once when crossed, not on every refresh, poll, session switch, or restart, and never from partial or truncated Project data. Acknowledgement is per-project and durable across restarts in the plugin's SQLite store. Notifications are toggleable in Settings and enabled by default; disabling them does not affect accounting or rendering. Contributed by #26, shipped in #42.

- **Subagents viewport and scrollbar.** The expanded Subagents section now sizes to `min(actual visible content height, max viewport height)` up to the two-entry viewport, so a single collapsed group occupies only one row and expanded agent details grow the container only as needed instead of reserving blank space for two entries. The scrollbar is gated on overflow only; it appears anchored to the right from its first frame with no left-side square artifact during the non-scrollable → scrollable transition. No clipped cue is rendered; additional groups scroll once the viewport cap is exceeded. Contributed by #25, shipped in #36, and #33, shipped in #41.

- **Carried docs.** Sidebar screenshots and the simplified `opencode-plugin` skill documentation from #40 are included in this tag's base with no additional behavior change.

## Upgrade

From 1.1.1 (or earlier):

- **Pinned users**: set the pin to `1.2.0` in your TUI config, then restart OpenCode.
- **Unpinned users**: OpenCode resolves `latest` on launch — restart OpenCode to pick up 1.2.0.

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["opencode-tokenmeter-tui"]
}
```

OpenCode installs TUI plugins cache-first. To update a cached install, remove the package cache directory and restart:

```bash
rm -rf ~/.cache/opencode/packages/opencode-tokenmeter-tui@latest
```

If you pinned a specific version, remove that version's cache directory instead. No `npm install` step is required. After restart the banner, sidebar, footer prompt icons, percentage cache mode, and milestone toasts at the next Project magnitude are live.

## Rollback

`1.1.1` remains a fully loadable published version. If 1.2.0 regresses:

- **Users**: pin back to `1.1.1` in the TUI config (or remove the plugin entry) and restart; report the failure so a `1.2.1` can be cut.
- **Maintainer**: the release pipeline is tag-driven (`v1.2.0` → preflight → publish → verify). A regression is corrected by cutting the next patch tag, not by re-pointing `1.2.0` — npm versions are immutable. Keep this document as the single release record until the next tag renames it.
