# v1.0.0 — TokenMeter: live token usage for the OpenCode TUI

TokenMeter's first stable release: a live sidebar for the OpenCode TUI that shows the active session's cumulative token spend, thinking, cost, and cache breakdown — plus its recursive delegation tree — and an all-time Project total that survives session deletion, restarts, and concurrent OpenCode processes.

## What changed

### A live usage sidebar for the OpenCode TUI

TokenMeter registers a `sidebar_content` slot (order 95) that renders a collapsible panel for the active session and every delegated descendant. Host events invalidate the affected session; a debounced reconcile rehydrates usage from the authoritative client messages (replace, never merge), so a stale in-memory mirror can never win over fresh data. The panel starts collapsed and never remounts to repaint. ([#2](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/2))

### Cumulative spend, not context-window guesswork

The headline number is each session's complete cumulative token spend — `Σ input + Σ output + Σ reasoning + Σ cache.read + Σ cache.write` across all assistant messages — the exact reconstruction of the provider's billed `tokens.total`, verified against a real payload. Every component keeps a per-field high-water so compaction can never lower the displayed spend or its breakdown. ([#2](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/2))

### Project totals that survive deletion

The Project section sums the authoritative live `session.list` (fetched with an explicit 10_000-session limit) plus one deleted-session aggregate per project, persisted in a plugin-owned SQLite store with exactly-once tombstone admission — duplicate deliveries, cascades, and concurrent TUIs never inflate totals, and a truncated list fails closed instead of showing a partial sum. ([#3](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/3))

### A release pipeline you can audit

Releases are tag-driven: pushing a stable `vX.Y.Z` tag runs preflight → publication → verification in a protected `release` environment. npm publishing uses Trusted Publishing (OIDC) with provenance — no npm tokens exist — and the workflow carries minimum permissions and exact-tag checkouts. The release preflight runs the full CI gate set, including the dist artifact smoke test after the build. ([#4](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/4), [#8](https://github.com/jonasotoaguilar/opencode-tokenmeter/pull/8))

The project guides align with the SQLite persistence and OIDC release pipeline, the repository ships the plugin-development and npm security-configuration skills, and this version bumps the package to 1.0.0 for its first stable publication. ## Install

Register the plugin in your TUI config (`~/.config/opencode/tui.json` user-level, `.opencode/tui.json` project-level, or `tui.jsonc` — all work):

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["opencode-tokenmeter-tui"]
}
```

OpenCode resolves npm package names for TUI plugins and installs them automatically — there is no `npm install` step. Restart OpenCode after changing a TUI plugin or its `tui.json` entry.

## Known issues

- The sidebar glyphs are Nerd Font PUA codepoints: without a Nerd Font active in the terminal they degrade to missing characters. Every number still renders and the panel never crashes.
- The cache breakdown row (`R<read>|W<write>`) needs roughly 36 terminal columns of sidebar width; narrower sidebars omit the breakdown row rather than overflow.
- Project totals include deleted sessions from the first run of v1.0.0 onward; sessions deleted before the plugin's SQLite store existed are not counted retroactively.
