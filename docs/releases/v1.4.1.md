# v1.4.1 — Subagents scrolling patch: fixed wheel steps with full-entry reveal

Patch release that corrects Subagents panel scrolling. The viewport keeps its six-row layout (three collapsed agents visible at once); every wheel gesture moves exactly 2 rows in either direction, and expanding a subagent auto-scrolls the minimum distance needed so the full compact (4 rows) or precise (6 rows) entry is visible. Delivered via PR #146 for issue #49. No public API or config break.

## What changed

### Six-row Subagents viewport with fixed two-row wheel steps

The Subagents section keeps a six-row viewport that fits three collapsed agents at once. Manual wheel navigation is fixed: every gesture advances exactly 2 rows, up or down, through the installed `scrollAcceleration.tick() => 2` path. The earlier variable boundary-snapping behavior is removed, so scrolling feels uniform regardless of entry boundaries (PR #146, closes issue #49).

### Toggle-only auto-scroll reveals the full expanded entry

Adaptivity now lives only in the expand/collapse toggle. Expanding an agent moves the viewport the minimum distance required to show its complete entry — header plus 3 detail rows in compact mode (4 rows total) and header plus 5 detail rows in precise mode (6 rows total). The reveal is a no-op when the entry already fits, handles entries clipped above the viewport, and collapsing clamps back with no blank rows. The reveal waits for the committed row layout before adjusting, so the full expanded entry is actually visible after the toggle.

## Compatibility

Additive patch, backwards compatible. No config schema, TUI contract, or plugin API change. Existing installs keep working; no migration and no manual file moves are required. Behavior change is limited to Subagents panel scrolling and expand/collapse reveal.

## Upgrade

From `1.4.0` on the same plugin entry mechanism as documented in `skills/opencode-plugin/references/updating-plugins.md`:

- **Unpinned (bare) entry** `opencode-tokenmeter-tui` / `opencode-tokenmeter-tui@latest` — remove the bare cache directory and restart OpenCode; it reinstalls `1.4.1` automatically:

```bash
rm -rf ~/.cache/opencode/packages/opencode-tokenmeter-tui@latest
```

Then restart OpenCode. No config change.

- **Pinned to `1.4.0`** (`opencode-tokenmeter-tui@1.4.0` in `tui.json`) — remove that version's cache directory, update the pin to `1.4.1`, and restart:

```bash
rm -rf ~/.cache/opencode/packages/opencode-tokenmeter-tui@1.4.0
```

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["opencode-tokenmeter-tui@1.4.1"]
}
```

Or use the bare entry to track `latest`.

## Rollback

`1.4.0` remains a fully loadable published version on npm. If `1.4.1` regresses:

- **Users**: pin back to `1.4.0` in `tui.json`, remove that version's cache directory (`rm -rf ~/.cache/opencode/packages/opencode-tokenmeter-tui@1.4.1`), and restart; or remove the entry and restart. Report the failure so a `1.4.2` can be cut.
- **Maintainer**: the release pipeline is tag-driven (`v1.4.1` → preflight → publish → verify). A regression is corrected by cutting the next semver tag, not by re-pointing `1.4.1` — npm versions and Git tags are immutable. Keep this document as the single release record until the next tag renames it via `git mv`.
