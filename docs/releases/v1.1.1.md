# v1.1.1 — TokenMeter: native prompt preserved, session metrics inline

TokenMeter 1.1.1 is a patch release that fixes the duplicated prompt introduced by the 1.1.0 footer. The metric line no longer re-renders the host `api.ui.Prompt` through the `session_prompt` replace slot; the plugin registers only the `session_prompt_right` slot and renders a compact, single-line token readout inline at the right end of the host's ONE native prompt row. The prompt itself (and its native usage/status row) stays exactly as the host renders it.

## What changed

- **Native Prompt preserved once.** The `session_prompt` (replace) registration is gone. Replacing the prompt and appending a second usage/status row duplicated the host prompt's own status row; the plugin now touches only `session_prompt_right`, which shares the prompt's agent/model row. No `home_bottom` or unsupported `statusline` registration is added.
- **Metrics format value-first.** The line renders value-first metric pairs — e.g. `55K in · 7K out` — using the existing compact/precise number seams, the same ` · ` separator as the sidebar, and the same `…` truncation when the line exceeds the terminal width. The line never wraps.
- **Session-only accounting.** The footer reads the slot's current `session_id` and the canonical per-session cumulative high-water usage (`observedSessionUsage`) — the active session's own spend, excluding every delegated descendant. Home intentionally shows no metric.
- **Configurable footer.** `TokenMeter: Settings` toggles the footer master switch and each metric independently (input and output are enabled by default; total, reasoning, and cache are off until you enable them). A disabled footer or a session without observed usage renders nothing, keeping the host prompt intact.

## Upgrade

From 1.1.0 (or earlier):

- **Pinned users**: change the pin to `1.1.1` in your TUI config, then restart OpenCode.
- **Unpinned users**: OpenCode resolves `latest` on launch — restart OpenCode to pick up 1.1.1.

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["opencode-tokenmeter-tui"]
}
```

OpenCode installs plugin dependencies automatically — there is no `npm install` step. To update a cached plugin, remove `~/.cache/opencode/packages/opencode-tokenmeter-tui@latest` and restart.

**Operator note**: if your running instance still shows the duplicated prompt after updating, it is loading a stale `dist/tui.js` artifact from the plugin cache — remove the cache directory above and restart. No local configuration change is required; the source fix ships in this package.

## Rollback

1.1.0 remains a fully loadable published version. If 1.1.1 regresses:

- **Users**: pin back to `1.1.0` in the TUI config (or remove the plugin entry) and restart; report the failure so a 1.1.2 can be cut.
- **Maintainer**: the release pipeline is tag-driven (`v1.1.1` → preflight → publish → verify). A regression in 1.1.1 is corrected by cutting 1.1.2, not by re-pointing 1.1.1 — npm versions are immutable. Keep this document as the single release record until the next tag renames it.
